# skweezxd — сайт-портфоліо

Портфоліо графічного дизайнера: темний мінімалізм, галерея робіт з
повноекранним переглядом, секція «Про мене» та контакти. Контентом можна
керувати через вбудовану адмінку — без коду й редеплою.

**Живий сайт:** https://skweezxd-gallery.vercel.app
**Адмінка:** https://skweezxd-gallery.vercel.app/admin

Стек: **Next.js 16** (App Router) · **React 19** · **TypeScript** · **Tailwind CSS 4** · **sharp** · **Cloudflare R2**

## Адмінка

Роман заходить на `/admin`, вводить пароль і керує сайтом сам.

**Вкладка «Альбоми»** — створити альбом, перейменувати, змінити порядок на
головній, обрати обкладинку (будь-яка робота з цього альбому; поки не обрано —
перша), видалити. Видалення альбому **не видаляє роботи** — вони просто стають
нерозподіленими.

**Вкладка «Роботи»** — завантажити фото (перетягуванням або через вибір
файлів), змінити підпис, призначити альбом, пересунути вище/нижче, видалити.
Над дропзоною обирається альбом, у який підуть нові завантаження.

**Вкладка «Тексти»** — ім'я, роль, локація, слоган, опис для пошуку,
бейдж «Відкритий до нових проєктів», email, соцмережі, список послуг та
інструментів, заголовок і абзаци секції «Про мене».

Зміни з'являються на сайті одразу.

> **Робота без альбому на сайті не показується** — вважається чернеткою.
> Це зручно: можна залити фото заздалегідь, а опублікувати пізніше, просто
> призначивши їм альбом. На головній видно обкладинки альбомів; клік по
> обкладинці веде на сторінку альбому `/album/<id>` з його роботами.

### Налаштування (один раз)

Фото й дані зберігаються у **Cloudflare R2** (безкоштовно: 10 ГБ, 1 млн
операцій запису та 10 млн читання на місяць).

**1. Бакет.** Cloudflare → R2 → **Create bucket**, назва на твій розсуд.

**2. Публічна адреса.** Бакет → Settings → **Public Development URL → Enable**.
Скопіюй адресу виду `https://pub-….r2.dev` — саме звідти сайт вантажить фото.

**3. Ключі доступу.** R2 → **Manage API Tokens → Create API Token**, права
*Object Read & Write*, обмежені цим бакетом. Збережи Access Key ID і Secret
Access Key (Account ID видно там же).

**4. CORS.** Бакет → Settings → **CORS policy**: дозволені origins
`https://skweezxd-gallery.vercel.app` і `http://localhost:3000`, методи
`PUT` і `GET`, заголовок `content-type`. Без цього браузер не зможе
завантажувати фото.

**5. Змінні оточення** у Vercel (**Settings → Environments → Production**):

| Змінна | Що це |
| --- | --- |
| `R2_ACCOUNT_ID` | Account ID у Cloudflare |
| `R2_ACCESS_KEY_ID` | з API-токена |
| `R2_SECRET_ACCESS_KEY` | з API-токена |
| `R2_BUCKET` | назва бакета |
| `R2_PUBLIC_BASE_URL` | `https://pub-….r2.dev` |
| `ADMIN_PASSWORD` | пароль для входу в `/admin` |

Після цього — редеплой, щоб змінні підхопились.

> Поки сховище не налаштоване, сайт працює у резервному режимі: показує
> демо-роботи з `public/works` і тексти за замовчуванням, а адмінка чесно
> попереджає, що зберегти зміни не вийде.

### Локальна розробка

Ті самі змінні поклади у `.env.local` (файл у git не потрапляє). Без них
адмінка відкриється, але збереження буде недоступне.

## Запуск локально

```bash
npm run dev
```

Сайт відкриється на http://localhost:3000

## Резервний спосіб додати роботи (без адмінки)

Якщо R2 не налаштований, галерея читає папку `public/works`. Поклади
зображення туди — вони з'являться після наступної збірки.

**Формати:** `.jpg`, `.jpeg`, `.png`, `.webp`, `.avif`, `.gif`

**Порядок** задається числовим префіксом в імені файлу, **підпис**
будується з решти імені:

| Ім'я файлу              | Підпис на сайті |
| ----------------------- | --------------- |
| `01-brand-identity.png` | Brand identity  |
| `04-фірмовий-стиль.jpg` | Фірмовий стиль  |

> Файли `01-…` – `08-…` — це демо. Їх створює
> [`scripts/generate-placeholders.mjs`](scripts/generate-placeholders.mjs)
> перед збіркою, але **лише якщо папка порожня**. Щоб вимкнути — прибери
> рядок `"prebuild"` із `package.json`.

## Деплой

Сайт хоститься на Vercel. Контент з адмінки оновлюється без деплою —
редеплой потрібен лише коли змінюється код.

### Через Vercel CLI

```bash
vercel login
```

```bash
vercel --prod
```

### Автодеплой з GitHub (рекомендовано на майбутнє)

Створи репозиторій на GitHub, запуш туди проєкт і підключи його у Vercel
(**Add New → Project → Import Git Repository**). Після цього кожен `git push`
оновлюватиме сайт автоматично.

### Свій домен

Додається у Vercel: **Project → Settings → Domains**.

## Структура

```
src/
  app/
    layout.tsx             метадані з налаштувань, шрифти, локаль uk
    page.tsx               збірка секцій
    opengraph-image.tsx    прев'ю для соцмереж
    globals.css            палітра й базові стилі
    album/[id]/
      page.tsx             сторінка одного альбому
    admin/
      page.tsx             вхід або дашборд
      actions.ts           серверні дії (усі під перевіркою сесії)
      AdminDashboard.tsx   вкладки й повідомлення
      AlbumsPanel.tsx      створення й керування альбомами
      WorksPanel.tsx       завантаження та керування фото
      SettingsPanel.tsx    форма текстів
    api/upload/
      route.ts             підписане посилання для завантаження у R2
  components/
    SiteHeader.tsx         навігація
    Hero.tsx               перший екран
    Works.tsx              секція галереї (альбоми або роботи)
    AlbumsGrid.tsx         обкладинки альбомів на головній
    GalleryGrid.tsx        сітка робіт 16:9 (клієнтський компонент)
    Lightbox.tsx           повноекранний перегляд
    About.tsx              про мене
    SiteFooter.tsx         контакти
  lib/
    storage.ts             доступ до Cloudflare R2 (S3 API)
    settings.ts            тексти сайту + значення за замовчуванням
    albums.ts              альбоми та вибір обкладинки
    plural.ts              українське відмінювання після числівника
    works.ts               список робіт (R2 або public/works)
    auth.ts                пароль і сесія адмінки
    site.ts                початкові значення для налаштувань
```
